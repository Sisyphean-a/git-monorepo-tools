# 2026-10

- 2026-10-22 · [功能] 侧栏与仓库设置按 Git 工作树分组，多工作树折叠展示，单工作树保持平铺；Repo 仍是工作树级操作对象。范围：workspace
  原因：同一仓库的多个 worktree 被当作独立仓库，侧栏和设置列表膨胀，收藏、搜索与状态缺少仓库级视图。

- 2026-10-22 · [缺陷] 历史页排除 stash 与 notes 引用，避免其提交、refs/stash 标签和额外父提交撑乱提交图。范围：workspace
  原因：`git log --all` 把 `refs/stash` 和 `refs/notes/*` 当作历史起点，stash 以合并提交出现并产生多余分支；单独 stash/notes 变化还会触发无意义的历史重载。

- 2026-10-22 · [功能] 历史页增加全部分支、当前分支和选择分支范围，提交图轨道与前端加载量设置上限；stash 仍不进入分支历史。范围：workspace
  原因：全分支历史在分支多时难以定位，提交图轨道和无限加载会挤压消息区并增加内存；需要在不加载全历史的前提下让其他分支可见。

- 2026-10-16 · [演进] 后台任务弹窗默认展示全部项目任务，外部入口仍只统计当前项目活跃任务。范围：workspace
  原因：用户要求默认集中查看任务，但保留项目入口的原有展示语义；扩大可见范围后，配置修改与运行操作仍必须绑定任务自身所属项目。

- 2026-10-16 · [缺陷] 文件页失焦只暂停自动检查，保留当前文件树、正文和预览，离开文件页仍释放阅读数据。范围：workspace
  原因：失焦与离开文件页共用 `session.release()`，导致用户切到其他应用时正在阅读的内容变空白；资源节省应暂停后台读取，而不是清空仍可见的阅读画面。

- 2026-10-15 · [缺陷] 提交信息生成按 AI 服务错误解释原因与建议，保留响应状态、原文与请求标识，不再套用 Git 失败处理。范围：workspace
  原因：AI 请求读取超时被通用错误规则解释为 Git 操作超时，DeepSeek 的繁忙信息又未被识别；后端读取响应失败时直接返回读取错误，丢掉已收到的服务商错误正文。

- 2026-10-15 · [功能] AI 提交设置增加独立 HTTP 代理开关、主机和端口，明确直连与手动代理两条路径，不跟随 Git 代理。范围：workspace
  原因：Git 子进程的代理环境与 Go AI HTTP 请求不是同一路径；原 AI 请求依赖环境代理，设置中无法单独决定路由，容易把 AI 网络问题误当成 Git 配置问题。
  证据：`snapshot/ai_proxy_test.go`（实际 HTTP 代理、HTTPS CONNECT 与环境隔离）。

- 2026-10-14 · [重构] 快照回写版本与文件阅读请求分别收归状态模块和阅读会话，界面不再持有内部版本表或请求编号。范围：workspace
  原因：快照回写判断散在 React hook，文件读取、渲染与释放散在组件的多个入口，难以通过同一公开面验证跨交互、折叠与失焦后的迟到响应。

- 2026-10-13 · [演进] 启动、自动和侧栏手动扫描的远端刷新改为按并发数逐仓 Fetch、逐仓回写，不再等全量远端快照完成才展示结果。范围：workspace
  原因：本地扫描结束时界面已退出“检查中”，旧远端刷新却要等整批仓库 Fetch 与重试收尾才能返回；慢仓库延迟其他已完成仓库的反馈，代理加速无法消除这种展示等待。

- 2026-10-13 · [缺陷] 全部 Pull 先检查远端再判断是否拉取，本地状态与远端检查结果独立，避免漏拉提交及本地轮询清除远端失败反馈。范围：workspace
  原因：批量操作按旧远端记录的 `Behind == 0` 跳过 Fetch，使尚未获取的新提交被报告为已同步；Fetch 错误原归入 `scanError`，下一次成功本地轮询又把它清除，使远端失败看起来已恢复。
  证据：`snapshot/remote_check_test.go`（真实临时远端复现）。

- 2026-10-13 · [缺陷] 历史按 HEAD 与全部引用版本更新，Fetch 带来的远端提交及标签变化不再因 HEAD 未变而滞留旧列表。范围：workspace
  原因：后端 `git log --all` 已包含远端引用，但前端历史失效只跟踪 HEAD；完整本地快照又可能丢掉阅读版本，造成漏刷新或无变化时重载。

- 2026-10-13 · [演进] 空固定终端离开页签或项目立即回收，替代一分钟延迟，并保留草稿和在途输入。范围：workspace
  原因：延迟回收不必要地保留空 Shell，且旧条件只观察项目切换；立即回收还暴露了创建未完成就报告关闭、快速返回复用将被关闭会话的竞态。

- 2026-10-13 · [缺陷] 终端自动协议回复不再被当作输入草稿阻止空固定终端回收。范围：workspace
  原因：xterm `onData` 同时发送用户输入和自动回复，旧追踪器只正确跳过 CSI 与 BEL 终止的 OSC，DCS 状态回复中的正文被记为草稿；ST 终止的 OSC 又会误吞其后的真实输入。实机反馈还暴露了交付误判：当时运行的桌面文件是前一天旧包，源码测试与前端构建并不证明已运行新桌面逻辑。

- 2026-10-13 · [功能] 增加应用内后台任务弹窗：按项目保存命令与工作目录，手动启动、停止、查看有界日志，收起不占终端 tab。范围：workspace
  原因：开发服务器与监听命令需要持续运行，但独立终端占用主区域；用户明确选择资源优先，放弃交互输入，仅保留任务管理与只读输出，后台不延伸到应用退出之后。

- 2026-10-12 · [缺陷] 未跟踪文件在 status 与读取之间消失时丢弃该条目，不再把整个仓库标为扫描失败。范围：workspace
  原因：Vite 5.4.21 加载 `vite.config.ts` 会写同名 `.timestamp-<时间>-<随机>.mjs` 并在 import 后立即 unlink，文件存在期只有几毫秒；后台 2 秒/10 秒轮询撞上该窗口时，把读取失败升级为 `Repo.ScanError` 的实现（`df3629e` 引入）会让仓库显示“扫描失败”并阻塞 Pull，而文件已不存在意味着它不可能是真实变更，属于竞态而非读取失败。
  证据：Vite 的 `loadConfigFromBundledFile` 写入后立即 unlink。

- 2026-10-12 · [演进] 资源监控历史改为等宽时间桶聚合：桶内数值按样本覆盖时长加权平均，桶数超过上限时把桶宽翻倍并整体重新分桶，取代“越旧越粗、越新保持原始”的逐段减半降采样。范围：workspace
  原因：旧降采样只合并中间样本、始终保留首尾原始值，同一张图上旧点覆盖几分钟、新点只覆盖一次采样；面板打开后每 5 秒采样与后台每 30 秒采样又叠加成密度差，曲线前段平直、后段毛刺（用户实际观察到的现象）。等宽桶让分辨率对整段历史一致，并让两种采样频率落在同一组点上；平均值一律由累加的总和与权重算出，不在平均值之上再平均，未知样本既不参与平均也不占用权重。

- 2026-10-12 · [缺陷] 文件页签右键“在资源管理器中打开”按被点击的条目定位：目录打开该目录，文件打开所在目录并选中文件；右上角“文件夹”按钮仍打开仓库根目录。范围：workspace
