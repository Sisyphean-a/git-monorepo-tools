- 2026-09-22 · [缺陷] 修复工作区列表刷新链路：完整快照不再被交互跨越丢弃，改由 `mergeSnapshotPreservingInteractions` 保留交互仓库结果后应用；渐进启动扫描结束后轮询接管“检查中”仓库（自动扫描关闭时一次性补齐）；单仓更新不再改写工作区扫描时间；设置类刷新不访问远端，完整刷新统一驱动界面“扫描中”状态；添加仓库入口去重、分类计数与折叠展开、设置弹窗按钮文案同步修正。范围：workspace
  原因：`snapshot-coordinator` 的交互版本门槛把承接列表组成的完整快照和后台单仓轮询一并丢弃，添加、移除、忽略或恢复仓库后侧栏不更新且无提示；启动扫描被交互中断后未扫描仓库永久停在检查状态，自动扫描关闭时无法自愈；`mergeSidebarRepoUpdate` 和 `mergeRepoSnapshotUpdate` 用单仓时间覆盖工作区扫描时间；`refreshSnapshot` 对每次设置变更都执行带重试的远端 fetch，放大了被交互跨越的窗口；`addScanRoot` 在刷新失败时不返回已持久化设置，会让设置弹窗草稿在后续保存时覆盖新目录。
  当前依据：`requirements/CONTEXT.md`、`architecture/INDEX.md`。

- 2026-09-22 · [演进] 自定义命令不再受“操作超时”约束：`RepoCommandRequest` 移除 `timeoutSeconds`，命令跑到自然结束；终止整棵进程树的行为只保留给 Git 命令。范围：workspace

- 2026-09-22 · [重构] 仓库文件树的 Git 忽略判断改为复用当前仓库唯一的 `git check-ignore --stdin` 会话，并在忽略规则、索引或仓库切换后重建，应用关闭时回收。范围：workspace
  原因：逐次展开目录都启动 Git 进程时，中位忽略检查约 85 ms，Windows 环境还会周期性出现 3.2–3.7 秒进程启动尖峰；会话复用后重复检查平均约 0.31 ms，包含目录读取与 129 个候选项过滤的基准约 2.1–3.9 ms/op。会话只缓存规则判定，忽略规则文件、`.git/index` 或仓库配置变化时重建，保证编辑 `.gitignore` 或被 `-f` 纳入版本控制的文件不会停留在过期结果。
  当前依据：`architecture/shared/wails-bridge.md`。
  证据：`snapshot/repo_ignore_session.go`、`snapshot/repo_files.go`、`snapshot/repo_files_test.go`、`snapshot/service.go`、`app.go`。
