- 2026-08-14 · [缺陷] Windows 图片粘贴识别标准位图和注册 `PNG`/`image/png` 格式，并对剪贴板短暂占用和图片延迟可用进行有界重试；检测到图片但未生成有效 PNG 时显式失败，已确认 Pi 会话读取为空时也不再回退为原始 `Ctrl+V` 并显示“已粘贴”。范围：workspace
  原因：应用图片预检只覆盖 `CF_BITMAP`/`CF_DIB`/`CF_DIBV5`，会把仅提供注册 PNG 数据流的图片判成空剪贴板；PowerShell 的 .NET 剪贴板读取异常还可能是非终止错误。Pi 文本粘贴切换为应用读取后，这个既有格式缺口开始直接影响已确认 Pi 会话，并触发无意义的 `Ctrl+V` 假成功。
  当前依据：`architecture/shared/terminal-runtime.md`。
  证据：`internal/desktop/clipboard_windows.go`、`internal/desktop/process_windows_test.go`、`internal/desktop/clipboard_windows_test.go`、`src/app/components/repo-terminal-shortcuts.ts`、`src/app/components/repo-terminal-shortcuts.test.ts`。

- 2026-08-13 · [缺陷] Windows 内嵌 Pi 的已确认身份跨 Pi 后台 cmd/npm 子进程临时改写的 OSC 0 标题保持，原始 LF 粘贴不再错误回退为会被 ConPTY 剥离边界的默认路径。范围：workspace

  当前依据：`architecture/shared/terminal-runtime.md`、`requirements/adrs/003-pi-windows-terminal-protocol-delivery.md`。

- 2026-08-13 · [缺陷] Windows 内嵌终端在已确认 Pi 会话中把文本粘贴的所有行结束符写为原始 LF，不再依赖 ConPTY 会剥离的 bracketed-paste 边界或修饰键 CSI，因此多行内容留在 Pi 编辑器而不逐行提交。范围：workspace
