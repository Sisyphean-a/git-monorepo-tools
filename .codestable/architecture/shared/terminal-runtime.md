# 终端运行时

- scope: workspace

## 契约

- 默认终端按仓库路径复用会话：`EnsureTerminalSession` 返回现有会话或创建新会话。用户新增的终端标签调用 `CreateTerminalSession`，即使同一仓库已有终端也必须创建独立会话；独立标签只在创建它的仓库处展示，切换仓库时不得复用或展示其他仓库的会话。工作区主标签的选择按仓库独立保留，首次打开仓库默认展示“变更”，切回仓库时恢复该仓库此前选择。关闭独立终端标签调用 `CloseTerminalSession` 时，必须先让会话不再可复用，再终止对应进程。`RestartTerminalSession` 只替换指定会话。
- 终端输入按会话串行写入；会话结束、未知会话和启动失败必须显式报错。
- Windows 的 `Ctrl+V`、`Alt+V` 和右键粘贴由应用读取剪贴板，并先尝试图片、确认无图片后再读取文本。图片读取不得用 `IsClipboardFormatAvailable` 或枚举格式作启动前门卫：延迟渲染和注册格式可能在该层返回假阴性。`App.ReadClipboardImagePath` 每次直接启动隐藏的 STA PowerShell，对 `.NET Clipboard.GetImage()` 以及注册的 `PNG`/`image/png` 数据流进行有界重试；专用退出码表示“确认无图片”，其他进程错误必须保留。只有非空 PNG 已落为 `%TEMP%/pi-clipboard-*.png` 后才按输入队列写入终端；读取异常、重试耗尽、文件缺失或空文件不得回退为文本或原始 `Ctrl+V` 并报告成功。图片导出使用独立的 5 秒冷启动预算，文本读取使用 2 秒预算。确认无图片后，`App.ReadClipboardText` 在同一锁定 OS 线程上完成 `OpenClipboard`、`GetClipboardData` 和 `CloseClipboard`，依次支持 `CF_UNICODETEXT`、`CF_TEXT`、`CF_OEMTEXT`；剪贴板为空或读取失败均不得发送原始 `Ctrl+V`。普通终端文本仍使用 xterm 的粘贴转换。已确认 Pi 会话则要求 `TerminalProtocolStateMachine` 同时观测到 Pi 的 OSC 0 标题（`π` 或 `π - <非空名称>`）、已请求且已由 xterm 确认的 bracketed paste、以及已请求或已协商的增强键盘；这时文本绕过 `terminal.paste`，将 `CRLF`、`CR` 和 `LF` 统一为原始 LF 后作为一次输入队列写入，图片仍写临时 PNG 路径。Pi 其后有普通输出正在等待 xterm 异步解析时，此资格仍有效；Pi 启动后的 cmd/npm 子进程可短暂改写同一终端的 OSC 0 标题，因此已确认的 Pi 身份必须跨这类非 Pi 标题保持，直到 Pi 关闭 bracketed paste 或增强键盘、出现不完整 Pi 标题，或会话结束后才回到默认路径。`repo-terminal-shortcuts.ts` 的 `windowsTerminalShortcutRules` 是 Pi Windows 输入归一的唯一配置位置：只有完整匹配的 `Shift+Enter`、`Ctrl+J`、`Ctrl+Backspace`、`Ctrl+V`、`Alt+V` 和有选区时的 `Ctrl+C` 被应用接管；其余按键及额外修饰键（包括 `Ctrl+←/→`）均保持 xterm 透传。`Shift+Enter` 与 `Ctrl+J` 都发送原始 LF，作为 Pi 跨终端稳定识别的新行输入；`Ctrl+Backspace` 发送 `Ctrl+W`，匹配 PowerShell PSReadLine 的按词删除绑定。
- 后端把终端输出合并为批次再通过 `repo-terminal-output` 事件发送；`terminalSession` 在发送 `repo-terminal-exit` 前关闭批次，所以尾部输出一定先到达。前端 `terminal-workspace` module 通过最小 `TerminalRuntime` interface 拥有会话 lifecycle、按 `sessionId` 的事件分发和按仓库的状态聚合，不能把一个终端的事件写入另一个终端。`TerminalSurfaceSession` 独占表面会话的启动、重启、当前会话记录、事件绑定和释放；会话创建和 xterm 绑定之间到达的输出和退出码按会话缓存，绑定时严格先回放输出再交付退出；每会话最多缓存 1 MiB，溢出必须显式失败且不得回放部分流。最后一个表面释放后清理未交付数据并停止重新缓存。各终端即使暂时不可见，也必须持续写入自身 xterm，项目切换不得由前端中转层裁剪输出或清空已有历史；历史淘汰仅遵循 xterm 自身的正常滚动缓冲策略。`RepoTerminalSurface` 只负责 xterm 显示、输入转发、协议事件转交和状态机效果执行，不直接订阅运行时事件、管理会话绑定或判断 Pi 兼容状态。
- 终端输出中的 HTTP(S) URL、`file://` 本机 URL 和 Windows 盘符绝对路径由 `RepoTerminalSurface` 注册的 xterm 链接提供器识别；只有用户按住 Ctrl 单击时才执行打开操作。HTTP(S) URL 交给系统浏览器，本地目标交给 `OpenLocalPath`；链接文本不是可信输入，不能拼入 shell 命令。无效、相对或不存在的本地目标必须在桌面层显式失败并显示终端提示。
- 应用关闭时终止全部会话；Windows ConPTY 进程放入 kill-on-close Job，避免遗留子进程。每次创建 Windows 终端时，后端都必须从系统和当前用户的注册表环境变量重新构建子进程环境：新增、更新或删除变量后，新终端立即生效，已存在终端保持原值；用户 `Path` 位于系统 `Path` 之前，且 `REG_EXPAND_SZ` 值在新环境中展开。
- `TerminalProtocolStateMachine` 接收交给 xterm 的输出副本、xterm 解析完成、终端输入和会话结束事件，拥有协议快照、Pi LF 粘贴资格及本地鼠标兼容的启停状态；它只返回快照变化和待执行的 xterm 效果，绝不筛除、改写、路由或直接写入原始输出。`RepoTerminalSurface` 执行这些效果并记录诊断，不再自行判断兼容条件。状态机在 xterm `onWriteParsed` 后读取公开的受控粘贴 mode，并在 `onData` 观察键盘协商响应。为处理跨块控制序列保留的输出尾部只能补全未完成的序列，不能重新应用此前已完整匹配的协议状态。它还从 OSC 0 标题识别默认 Pi 标题；Pi 身份在其输入协议存续期间跨子进程标题保持，且仅与已确认的 Pi 输入协议组合后决定粘贴运输路径。终端诊断弹窗因此能区分“Pi 已请求”“输出待 xterm 处理”“xterm 已确认”和“已收到协商响应”。
- Windows ConPTY 会在 Pi 0.84.1 全屏启动时丢弃 DEC 鼠标开启序列，却保留备用屏幕、受控粘贴和增强键盘序列；在受控粘贴已开启时，它还会在 `ConPTY.Write` 与 Node stdin 之间吃掉输入的 `ESC[200~`/`ESC[201~` 边界及修饰键 CSI，尽管前端和后端各自记录的是完整单次写入。目标机的直接 ConPTY→Node 原始输入探针确认单次写入的 LF 保持为 `0a`，所以 Pi 文本粘贴使用原始 LF 而非受控粘贴边界。`TerminalProtocolStateMachine` 只有在观察到“已进入备用屏幕、已请求受控粘贴、增强键盘已请求或协商、且未收到鼠标序列”这一完整 Pi 指纹时，才产生开启本地鼠标模式的效果；Pi 退出备用屏幕或终端进程退出时产生关闭效果，重置已清空的 xterm 时只清内部激活状态。会话结束后到下一次重置前，后续 xterm 解析回调不得基于退出前的协议快照重新产生开启效果。`RepoTerminalSurface` 只执行效果，原始后端输出不改写，也不伪造浏览器滚轮，使 xterm 原生把滚轮编码为 SGR 鼠标输入且不影响其他终端程序。
- 不依赖真实时钟的后端脚本化 host 和前端假 Wails 测试负责事件先后、缓存上限和回放；快捷键与协议观察器使用纯函数测试。真实 ConPTY/PowerShell 测试仅是带 `windows && integration` 标签的 Windows 烟测。
