# 工作区上下文

- scope: workspace

## 术语

- **仓库快照**：某一时刻用于界面展示的仓库状态、文件变更和远端关系；不包含提交历史、提交详情或文件差异正文。
- **已忽略项目**：用户在本地设置中指定、不纳入仓库发现和扫描的仓库路径；可从设置中恢复监控。
- **交互操作**：用户发起并需立即反馈的单仓 Git 操作，如暂存、取消暂存、提交、拉取、推送和单仓刷新。
- **后台刷新**：启动扫描、自动扫描或全局手动刷新触发的非交互式状态读取。
- **按需详情**：用户进入历史、日志或文件差异界面后才读取的数据。

## 稳定规则

- 交互操作按前台顺序执行，并以返回的单仓快照回写；后台刷新独立排队。侧栏手动扫描必须重新发现扫描根目录下的仓库，并以完整仓库快照更新界面；不得只刷新已存在的仓库。交互开始或结束后，较早的后台结果不得覆盖交互结果。
- 已忽略项目路径保存在本地设置中。启动、自动和手动扫描，以及批量操作的仓库发现都必须跳过这些路径；恢复监控后才可再次出现在仓库列表中。
- 组合操作在启动时绑定目标仓库，并按保存顺序完整执行；切换当前项目只停止旧项目的界面同步，不得取消、跳过或改向组合中的后续操作。
- 提交历史、提交详情和文件差异必须按需读取，不塞进基础仓库快照；历史页读取全部引用可达的提交，保留父提交哈希以渲染分支拓扑，并继续按页加载。
- 所有未跟踪变更按文件展示：使用 `git status --porcelain=v1 -b --untracked-files=all`，每个未跟踪文件对应一个 `FileChange`，计数和列表使用同一粒度。
- 未跟踪文件不设静默数量上限；大仓库性能问题应优化读取或交互，不得遗漏真实变更。
- Pull 前必须显式拒绝扫描失败、有冲突或有本地变更的仓库；默认策略为 `--ff-only`，不会自动 merge、rebase 或 stash。
- 用户收藏的仓库 ID 保存在本地设置中，并按收藏顺序排列。侧栏仅在当前扫描结果包含至少一个收藏仓库时展示“收藏”分组；收藏仓库只显示在“收藏”分组，不得同时显示在原有分类。应用启动时，当前扫描结果中的第一项收藏仓库为默认打开项目；没有可用收藏时沿用原有默认选择。
