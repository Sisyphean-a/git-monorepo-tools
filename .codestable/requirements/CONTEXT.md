# 工作区上下文

- scope: workspace

## 术语

- **项目 / 当前项目**：用户通常用“项目”指仓库所承载的代码；在本应用中说“当前项目”时，指当前选中的仓库。仓库还包含 Git 管理数据。
- **仓库**：包含项目代码及其 Git 元数据与历史的完整代码库；Git 操作以对应仓库为对象，前端模型为 `Repo`（`src/app/domain/types.ts`）。
- **主区域 tab**：主内容区的固定页签“变更、历史、文件、终端”；提到这四者之一的 tab 均指对应页签。未加限定的“终端 tab”特指固定的“终端”页签；点击“+”新增的是独立终端 tab。`WorkspaceMainTab` 联合包含四个固定值和 `IndependentTerminalTabId`（独立 tab ID），后者对应 `terminal-N`（`src/app/features/terminal/terminal-workspace.tsx`）。
- **仓库快照**：某一时刻用于界面展示的仓库状态、文件变更和远端关系；不包含提交历史、提交详情或文件差异正文。
- **远端检查**：对当前分支跟踪的远端执行 Fetch，记录检查成功或失败、完成时间及失败原文；它与本地工作区状态独立，不代表工作树已执行 Pull。
- **已忽略项目**：用户在本地设置中指定、不纳入仓库发现和扫描的仓库路径；可从设置中恢复监控。
- **交互操作**：用户发起并需立即反馈的单仓 Git 操作，如暂存、取消暂存、提交、拉取、推送和单仓刷新。
- **后台刷新**：启动扫描、自动扫描或全局手动刷新触发的非交互式状态读取。
- **按需详情**：用户进入历史、日志、文件浏览或文件差异界面后才读取的数据。
- **仓库文件浏览**：只读查看当前选中仓库工作树中的目录结构、文本文件正文及其高亮/Markdown 预览，不提供编辑或差异比较。
- **差异来源**：一次差异阅读所绑定的数据范围，取值为当前仓库的暂存变更、未暂存变更或某次历史提交差异；一个阅读会话只绑定一种来源。
- **暂存变更**：当前仓库 Git index 中已暂存、待提交的变更。
- **未暂存变更**：当前工作树相对 Git index 的变更；“变更区”在差异查看器语境中指此来源。
- **统一差异查看器**：应用内用于连续阅读一个差异来源的窗口，同时支持快速浏览和个人审查辅助，不承担评论、审批或协作审查。

## 稳定规则

- 资源监控是应用级只读入口，位于仓库头部文件夹按钮之前，与统一差异查看器共用弹窗尺寸。主进程的私有提交、工作集、CPU、句柄和 Go 运行时指标与全系统分页/非分页池分区展示；工作集包含共享页，不相加当成独占内存，内核池变化不得归因为本工具。File 内核对象指标来自全系统 `File` 池标签：存活数量是分配减释放得到的存活分配块，不是文件句柄数；占用是该标签分页池与非分页池的字节合计；每秒净增长用相邻有效快照的实际单调时间差计算，首次、上次 File 查询失败或时间不递增时为未知，负值表示净释放，另显示首末有效采样的会话平均速率。持续增长仅为排查线索，不能据此指名触发程序或引用持有驱动。File 查询失败时只将该组指标标为未知并显示独立错误，其他成功指标继续更新。子进程明细包含采样时的当前进程树与自有终端 Job 验证的存活成员，已退出进程不累计；父子关系本身不等于应用控制权，不在两者范围内的外部应用不纳入；子进程私有提交合计不含主进程，包含 WebView2、终端及其后代，不等于 `git.exe` 单独占用，也不等于驻留物理内存；后台采样不枚举进程树时明细为未采集，不得显示为零占用或空表；读取失败保留明确错误和未知指标。采样由原生采样器拥有并覆盖应用从打开到关闭的整个生命周期：后台约每 30 秒读取一次轻量数值，面板读取状态时续租约每 5 秒的高频窗口并附带进程树，停止读取约 15 秒后自动回到后台节奏；历史按等宽时间桶聚合：桶内数值按各样本覆盖的时长加权平均，未知样本既不参与平均也不占用时长权重，桶数超过上限时把桶宽翻倍并整体重新分桶，因此后台约每 30 秒与面板约每 5 秒两种采样频率落在同一条等宽曲线上、任何点都不会比其它点更粗或更细；没有覆盖时长的桶（只有启动基线）回退到已知原始值，由全部原始采样统计的峰值与全程趋势不受分桶影响；会话历史只覆盖当前运行期，不落盘也不跨重启恢复。CPU 按单调时间差与逻辑核数计算，只有同一 PID 与创建时间且累计时间单调时有效，首次采样或身份变化显示未知；采样失败保留上一次数据并明确标注失败；关闭应用时等待在途采样收尾、停止循环，再补记一次关闭边界；读状态与关闭不是原子操作，不能用关闭前后状态读数只差一次来排除合法的在途采样。监控不启动外部采样命令、不强制 GC、不清理系统内存。代码锚点：`internal/monitor/`、`app.go`、`src/app/domain/resource-monitor.ts`、`src/app/components/resource-monitor-modal.tsx`。

- 资源监控的级联明细按“项目 → 终端会话 → 进程树”展示，同项目的多个终端分别保留会话身份。项目是终端创建时绑定的仓库 ID 与路径，终端中执行 `cd` 不改变归属。归属只接受管理器记录的根进程或经自有 Windows Job 验证的成员，采样必须同时匹配 PID 与创建时间；中间父进程退出时，仍存活的已验证成员独立保留并提示父级缺失，不能按命令行路径猜归属。WebView2 的应用界面分支与其他 / 未确认归属进程分别展示；归属查询失败或冲突明确标注，任何未知指标或不完整归属都不能汇总成完整零占用。进程行区分自身私有提交与包含自身的子树合计，项目和终端合计只计各自进程一次，不把父行与子行再次累加；工作集不做独占合计。Pi、Codegraph、context-mode 和语言服务仅按明确入口脚本或专用进程名生成固定用途标签，原始命令行及业务参数只在本次原生查询内使用，不传给前端、不写入采样历史或日志，以免参数中的密钥泄露；未识别时保留进程名，读取失败明确提示。终端归属也只在面板高频采样时查询，不增加后台 Job 枚举。代码锚点：`internal/terminal/resources.go`、`internal/terminal/resources_windows.go`、`internal/monitor/terminal_scopes.go`、`internal/monitor/process_label_windows.go`、`src/app/domain/resource-process-tree.ts`、`src/app/components/resource-process-tree.tsx`。

- 读取资源只清理应用自身持有的可重建数据与会话，不调用系统级内存清理、不承诺回收驱动持有的内核对象。窗口失焦或不可见时暂停周期 Git 状态与远端扫描，正在运行的请求正常收尾；重新聚焦后当前项目立即刷新。切换项目释放离开项目的读取缓存，离开文件页或窗口失焦释放正文、渲染结果、目录缓存和持久 Git 忽略检查会话，只保留恢复阅读所需的轻量位置与偏好。每 5 分钟清理读取缓存与忽略检查会话，后续读取按需重建；未跟踪文件只缓存大小、修改时间、文件模式及行数，元数据变化即重读，命中不延长 5 分钟有效期，已删除或已跟踪文件移出缓存；读取失败不缓存，并显式标记仓库扫描错误，不把失败当成零行文件；status 之后才被删除的未跟踪文件（临时文件竞态，如 Vite 的 `.timestamp-*.mjs`）按已删除处理，丢弃条目且不标记扫描错误。相同大小与修改时间的非常规改写在下一次过期重读时校正。文件列表不得因优化而截断。终端内容和运行中的命令不因切换、失焦或周期清理而丢失或终止；没有使用内容的固定终端离开即回收，判定和生命周期由[终端运行时](../architecture/shared/terminal-runtime.md)统一定义。关闭应用才停止维护任务、关闭读取资源并终止应用托管的内置终端与自定义命令进程树，外部终端和系统文件管理器不受影响。代码锚点：`snapshot/read_resources.go`、`snapshot/git_status.go`、`snapshot/command_runner.go`、`app.go`、`src/app/application/use-window-activity.ts`、`src/app/application/use-repo-status-polling.ts`、`src/app/components/repo-files-tab.tsx`。

- 交互操作按前台顺序执行，并以返回的单仓快照回写；后台刷新独立排队。侧栏手动扫描必须重新发现扫描根目录下的仓库，并以完整仓库快照更新界面；不得只刷新已存在的仓库。完整快照决定仓库列表组成（新增、移除、忽略、恢复），即使读取跨越了交互操作也必须应用；快照读取期间被交互更新的仓库保留本地结果，其余字段以快照为准。早期后台单仓结果不得覆盖交互结果。单仓更新不改变工作区扫描时间。
- 启动、自动和侧栏手动扫描中的远端刷新按设置的并发数逐仓执行 Fetch，完成一个仓库就立即回写它的状态或错误，不等待整批远端刷新完成；整批收尾前仍保留全局扫描忙碌态。本地完整快照先应用，远端阶段不再用最后一份全量快照覆盖逐仓结果。高频状态轮询只读取本地记录，不替代 Fetch。代码锚点：`src/app/application/snapshot-coordinator.ts`、`src/app/application/use-snapshot-refresh.ts`、`src/app/application/use-workspace-state.ts`。
- 设置变更（添加或移除扫描目录、忽略或恢复仓库、保存设置）只做本地仓库发现刷新，不访问远端。渐进启动扫描结束或被中断后，后台轮询必须接管仍处于“检查中”的仓库；自动扫描关闭时对其执行一次性补齐，避免仓库永久停在检查状态。
- 已忽略项目路径保存在本地设置中。启动、自动和手动扫描，以及批量操作的仓库发现都必须跳过这些路径；恢复监控后才可再次出现在仓库列表中。
- 组合操作在启动时绑定目标仓库，并按保存顺序完整执行；切换当前项目只停止旧项目的界面同步，不得取消、跳过或改向组合中的后续操作。
- 提交历史、提交详情、仓库文件树、文件正文和文件差异必须按需读取，不塞进基础仓库快照；历史页读取全部引用可达的提交，保留父提交哈希以渲染分支拓扑，并继续按页加载。历史读取版本须覆盖 HEAD 与全部引用变化：Fetch 只移动远端分支、增加其他分支或改变标签而 HEAD / ahead / behind 不变时，也须更新历史；Fetch 本身不是新提交，不伪造操作记录。单仓轮询和完整周期快照在 HEAD 与引用未变时保留提交列表、选择、详情和阅读位置，不因时间或对象替换重载。引用摘要读取失败归入本地扫描错误，不冒充引用未变；只传递轻量引用版本，不提前读取提交列表或详情。代码锚点：`snapshot/git_history.go`、`snapshot/service.go`、`src/app/domain/repo-snapshot-merge.ts`、`src/app/components/workspace.tsx`。
- 仓库文件浏览是独立的只读入口，位于主区域“历史”之后、“终端”之前：文件树直接展示仓库根目录的子项，不重复展示仓库根节点；目录展开时按需读取一级子项，折叠时释放该子树缓存；点击文件或切回仓库恢复阅读位置时才读取正文。切换仓库只保留各仓库的选中文件、展开目录、树与正文滚动位置、预览模式和换行偏好，不保留其他仓库正文；当前 Tab 重新激活或窗口重获焦点时更新已展开目录并检查当前文件版本，活跃且聚焦期间每 3 秒只检查当前文件元数据，版本变化才重读正文，不随后台仓库快照轮询重读文件。`.git` 和符合 Git 忽略规则的项不出现在树中，二进制文件和超过 1 MiB 的文件不加载正文并明确提示，所有请求路径必须保持在当前仓库内。文件树图标按文件类型区分。预览区与文件树之间的分割条可拖动或按 ←/→ 调整文件树宽度：宽度不小于 220px，容器放得下时为预览区保留至少 320px；宽度按项目保存在本地设置中，重开应用后按项目恢复。
- 文件预览在纯文本之上增加只读展示：已知扩展名按对应语言高亮，Markdown 默认渲染预览并在“预览/原文”之间切换；正文默认自动换行，可关闭以查看横向滚动，横向滚动条需清晰且可拖动。高亮与渲染只作用于当前文件，超过 256 KiB 的文件只显示纯文本并提示；渲染失败时保留已读到的纯文本并提示失败，不得把渲染失败显示为读取失败。高亮与 Markdown 渲染器按需加载，只有打开代码或 Markdown 文件时才取用。当前文件查找从预览右上角入口或 `Ctrl/Cmd+F` 打开，支持大小写、全字、正则、结果计数和循环切换上下项；它只查找已加载的当前正文，不触发仓库级搜索，查找时以原文定位匹配，关闭后恢复原有高亮或 Markdown 视图。
- Markdown 预览把段内单个换行按硬换行渲染（`src/app/features/files/markdown.ts`），与 VS Code、Typora 等编辑器一致，不采用 CommonMark 折叠软换行的默认行为；仓库中按单行书写的文档因此在预览中保持行结构，与正文折行偏好无关。
- Markdown 预览不执行仓库内容里的 HTML（原始标签按文本显示），只允许 http/https/mailto 外链、仓库内路径与安全的文档章节锚点。外链交给系统默认浏览器，相对或根路径链接解析到当前文件所在目录或仓库根，并在文件树中展开并打开目标文件；同文件和跨文件的 `#章节` 跳至目标标题，找不到标题时给出提示；越出仓库的路径、仓库内图片与不安全协议一律不打开。
- 统一差异查看器只作用于当前选中仓库，并且一次只绑定一个差异来源：暂存变更、未暂存变更或历史提交差异。工作区暂存和未暂存同时存在时默认未暂存变更；仅存在一种时默认该来源；不查看未跟踪文件或分支之间的差异。历史普通提交与其父提交比较，合并提交与第一父提交比较，根提交与空树比较。
- 统一差异查看器的入口位于当前仓库头部的外部终端按钮旁，弹窗属于应用内部且与外部终端无关；历史提交可通过独立入口进入同一查看器。弹窗每次打开均重新读取当前 Git 状态，不保留上次选择、滚动、展开或审查进度；文件清单完整可导航，差异正文按当前文件按需读取并在切换或关闭后释放，不保留跨文件缓存。左右代码列固定各占 50%，两列纵向滚动联动、横向滚动独立；正文隐藏 Git 文件头、索引和 hunk 标题，只展示代码行，长行自动换行并按实际渲染高度校准虚拟行位移，保证长差异可连续阅读且不重叠。个人审查标记仅存在当前会话，不提供评论、审批或协作。
- 仓库快照以 `git status --porcelain=v2 --branch -z --untracked-files=all --no-renames` 为工作树状态依据，差异统计只补充行数与大小，不能决定文件是否存在于变更列表。换行符规范化、文件模式、索引状态或子模块可能使 status 标记修改但文本 diff 为空，此时仍保留文件、暂存归属和变更计数，不能显示为干净；展开空差异时明确解释这种区别。`--no-renames` 与逐暂存区的 diff 读取保持同一粒度。每个未跟踪文件对应一个 `FileChange`，计数和列表使用同一粒度。代码锚点：`snapshot/git_status.go`、`src/app/components/file-diff.tsx`。
- 未跟踪文件不设静默数量上限；大仓库性能问题应优化读取或交互，不得遗漏真实变更。
- 本地工作区状态与远端检查结果独立：`Repo.status`、`scanError` 只描述本地读取，`remoteCheck` 描述远端检查结果。Fetch 失败不得伪装成本地扫描失败，也不得被成功的本地轮询、完整本地快照或纯本地交互清除；同分支、同远端名称的检查结果保留至下一次实际检查更新，分支或远端名称变化后显示未检查。成功的单仓 Pull 包含 Fetch，可更新成功结果。界面区分本地更新时间与远端检查完成时间，远端未知或失败时不能展示已确认同步的绿色标记；成功 Fetch 后的本地读取失败仍须保留 `scanError`。代码锚点：`snapshot/git_status.go`、`snapshot/service.go`、`src/app/domain/repo-snapshot-merge.ts`、`src/app/components/repo-list-status.tsx`、`src/app/components/workspace-parts.tsx`。
- Pull 前必须显式拒绝本地扫描失败、有冲突、有本地变更或没有远端跟踪分支的仓库；本地变更同时检查文件列表与变更计数，错误保留扫描原因或受影响文件路径。默认策略为 `--ff-only`，不会自动 merge、rebase 或 stash。全部 Pull 必须先 Fetch，再按最新远端关系判断同步、分叉或需要拉取；Fetch 期间安全条件变化时再次拒绝 Pull，Fetch 失败时报告失败而非“已同步”。没有执行 Pull 的成功或失败检查也须回写远端结果。本地领先但无需拉取时报告无需 Pull，不能声称已同步。
- 右侧 Git 操作及提交信息生成失败时，展示操作名称、目标仓库、原因、处理建议和可选中复制的原始错误。已识别的错误按证据解释；未知错误明确无法自动判定，不丢弃详情或只显示“操作失败”。忙碌态与错误按发起仓库保留，切回后仍可查阅，运行中同仓库按钮保持禁用；开始该仓库的下一次操作清除其旧错误。切换仓库后迟到的失败只写回原仓库，不得显示到新仓库或写入全局刷新错误。单仓与批量操作后状态读取失败须区分“操作已完成但刷新失败”，扫描失败快照仍需回写以展示真实状态；放弃更改若已重置已跟踪文件而未跟踪文件清理失败，须显式说明部分完成，不能暗示已回滚。展示层不自动修改 Git 状态或绕过安全检查。代码锚点：`src/app/application/repo-action-error.ts`、`src/app/application/use-repo-actions.ts`、`src/app/features/commands/use-repo-command-panel.tsx`、`src/app/components/ai-commit-panel.tsx`、`snapshot/operations.go`。
- 用户收藏的仓库 ID 保存在本地设置中，并按收藏顺序排列。侧栏仅在当前扫描结果包含至少一个收藏仓库时展示“收藏”分组；收藏仓库只显示在“收藏”分组，不得同时显示在原有分类。应用启动时，当前扫描结果中的第一项收藏仓库为默认打开项目；没有可用收藏时沿用原有默认选择。
